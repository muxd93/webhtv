## 10. 已知未修 / 已决定不做

以下都是**明确决定不做**的项，验收时看到也不要再提，避免重复讨论：

1. **`resConfigs` 与繁体**：打包只保留 `zh-rCN` / `zh-rTW` / `en` 三种资源，其它语言被裁掉；已决定不放开（包体积优先）。
   繁体本身已入包，但仍有 19 条文案缺口（CSP「排序」11 条、代理「自动识别」5 条、无节目单 / 推送图片 / 搜索列名），属已知未补，不阻塞发布。
2. **`RulePool` 永久并集**：多仓的规则池是跨仓永久并集，不做按仓隔离。后果是同名接口在不同仓之间互相可见——这是已接受的取舍。
3. **跨子仓频道合并**：不同子仓的直播频道不做合并去重，同一个频道可能出现多次。
4. **HTTP 磁盘缓存**：不做磁盘级 HTTP 缓存，只有内存缓存；同一请求重复发会再走网络。

## 11. 已知测试侧遗留

- `InlineTasksTest` 已改成虚拟时钟，不再依赖真实等待。
- 仍有若干用例依赖真实墙钟（弹幕 WebSocket 集成、弹幕吞吐负载、Exo 优先级数据源的负向等待、mpv 字体配置的 mtime 等待）。它们在单机独占跑时稳定，两个 flavor 并发跑时可能抖动，属测试侧问题，不影响真机行为。
- `LiveDanmakuPipelineLoadTest` 按真实速率压测并断言精确条数，机器负载高时最容易抖；如需稳定基线，建议单独跑它。
